# 🖨️ ระบบคิวพิมพ์ 3D + สต็อกวัสดุ + แจ้งเตือนกลุ่ม LINE OA

ต้องใช้ Node.js 22.13 ขึ้นไป และไม่ต้อง `npm install` เพราะใช้ SQLite ที่มากับ Node อยู่แล้ว

## เริ่มใช้งาน
```bash
cp .env.example .env     # แล้วใส่ค่า LINE
npm start                # เปิด http://localhost:3000
```

## ตั้งค่า LINE OA (ทำครั้งเดียว)
1. ไปที่ https://developers.line.biz → สร้าง Provider → สร้าง **Messaging API channel** (ได้ LINE OA มาด้วย)
2. แท็บ *Basic settings* → คัดลอก **Channel secret** ไปใส่ `LINE_CHANNEL_SECRET`
3. แท็บ *Messaging API* → กด Issue **Channel access token** ไปใส่ `LINE_CHANNEL_ACCESS_TOKEN`
4. ตั้ง **Webhook URL** = `https://โดเมนของคุณ/webhook` แล้วเปิด *Use webhook*
   (ถ้ารันในเครื่อง ใช้ `ngrok http 3000` หรือ Cloudflare Tunnel เพื่อให้ได้ https)
5. ใน LINE Official Account Manager → Settings → **เปิด "Allow bot to join group chats"** และปิด Auto-reply
6. เชิญบอทเข้ากลุ่ม LINE → บอทจะจำกลุ่มให้อัตโนมัติ (หรือพิมพ์ `ตั้งกลุ่มนี้`)
7. ในหน้าเว็บ แท็บ "ตั้งค่า LINE" → กด **ส่งข้อความทดสอบ**

## 🛒 สินค้า / สั่งพิมพ์ (ดึงจาก Shopee)
1. ใน Shopee Seller Center ไปที่ **สินค้าของฉัน → แก้ไขหลายรายการ (Mass Update) → ข้อมูลการขาย** แล้วดาวน์โหลดไฟล์ `mass_update_sales_info_....xlsx`
2. ในหน้าเว็บ แท็บ **สินค้า/สั่งพิมพ์** กด **📥 นำเข้าจาก Shopee** แล้วเลือกไฟล์นั้น
   - นำเข้าซ้ำได้เรื่อย ๆ ระบบจะอัปเดตราคาและสต็อก Shopee โดยค่าที่ตั้งไว้เองจะไม่หาย
   - ระบบเลือกวัสดุให้อัตโนมัติจากสีในชื่อตัวเลือก (White/ขาว, Black/ดำ ...) ต้องเพิ่มวัสดุในแท็บสต็อกก่อน หรือกด 🎨 จับคู่วัสดุอัตโนมัติ ภายหลัง
3. กด **⚙ ตั้งค่า** ที่สินค้า เพื่อใส่ **ชื่อย่อ, กรัม/ชิ้น, นาที/ชิ้น** ครั้งเดียว ใช้ได้กับทุกสีของสินค้านั้น และซ่อนสินค้าที่ไม่ได้พิมพ์เองได้ (เช่น บอร์ด IKEA ของแท้)
4. ใส่จำนวน กด **+ เพิ่ม** ลงใบสั่งพิมพ์ แล้วใส่ชื่อลูกค้า/เลขออเดอร์ กำหนดส่ง และหมายเหตุ
5. กด **📤 ส่งเข้าคิว + แจ้งทีมใน LINE** ระบบจะสร้างงานเข้าคิว (1 งานต่อ 1 ตัวเลือก) และส่ง **ใบสั่งพิมพ์** เลขที่ `POyymmdd-nn` เข้ากลุ่ม

## ข้อความแบบการ์ด (Flex) มีปุ่มกด
งานใหม่มีปุ่ม **▶ เริ่มพิมพ์** งานที่กำลังพิมพ์มีปุ่ม **✅ เสร็จ / ❌ เสีย** และงานที่เสร็จมีปุ่ม **▶ เริ่มคิวถัดไป**
ทีมกดในกลุ่มได้เลย (ปุ่มจะพิมพ์คำสั่งเข้ากลุ่มให้ แล้วบอททำงานต่อ) ปิดได้ในหน้าตั้งค่า ถ้าอยากได้ข้อความธรรมดา

## ต้นทุน & สรุปประจำวัน
- ใส่ **ราคา/กก.** ของวัสดุ ระบบจะคำนวณต้นทุนวัสดุของแต่ละงาน (แสดงในข้อความ "พิมพ์เสร็จ", ประวัติ และแดชบอร์ด)
- **สรุปประจำวัน** ส่งเข้ากลุ่มอัตโนมัติตามเวลาที่ตั้ง (ค่าเริ่มต้น 18:00 เวลาไทย) มีจำนวนที่พิมพ์เสร็จ วัสดุที่ใช้ ต้นทุน งานเสีย คิวที่ค้าง และวัสดุที่ต้องสั่งเพิ่ม หรือพิมพ์ `สรุป` ในกลุ่มก็ได้

## คำสั่งที่พิมพ์ในกลุ่ม LINE ได้
- `คิว`: ดูคิวทั้งหมด
- `สรุป`: สรุปยอดวันนี้
- `สต็อก`: ดูวัสดุคงเหลือ
- `เริ่ม 12`: เริ่มพิมพ์งาน #12 บนเครื่องที่ว่าง
- `เสร็จ 12` หรือ `เสร็จ 12 85`: จบงาน (ระบุกรัมที่ใช้จริงได้)
- `เสีย 12`: บันทึกงานเสียและเพิ่มเข้าคิวใหม่
- `ช่วยเหลือ`: ดูคำสั่งทั้งหมด

## หลักการคิดสต็อก
- **คงเหลือ** = กรัมที่มีจริงในสต็อก
- **จองในคิว** = กรัมที่งานที่รอคิวหรือกำลังพิมพ์จะใช้
- **ใช้ได้** = คงเหลือ − จองในคิว (ถ้าติดลบแปลว่าต้องซื้อเพิ่มก่อนพิมพ์คิวให้หมด)
- ระบบตัดสต็อกตอนกด "เสร็จ" (ตามกรัมที่กรอก) และตอนพิมพ์เสีย (ตามกรัมที่เสีย)
- คิวเรียงตาม: กำลังพิมพ์ → งานด่วน → งานที่เข้าคิวก่อน

## ความปลอดภัย
ตั้ง `ADMIN_PASSWORD` ใน `.env` เพื่อล็อกหน้าเว็บ (ชื่อผู้ใช้ `admin`) ส่วน webhook ตรวจลายเซ็นของ LINE ด้วย Channel secret อยู่แล้ว

## 🌐 เชื่อมกับเว็บไซต์ (apps/web)
เมื่อลูกค้าอัปโหลด STL แล้วกด **ยืนยันสั่งพิมพ์** ที่หน้า `/upload` จะเกิดขั้นตอนนี้:
1. เว็บคำนวณราคาใหม่ฝั่ง server จากไฟล์จริง (ไม่เชื่อตัวเลขจาก browser)
2. ส่งไฟล์ STL เข้า `POST /api/external/files` แล้วสร้างออเดอร์ผ่าน `POST /api/external/orders`
3. งานเข้าคิวพร้อมเลขออเดอร์, ชื่อ/ช่องทางติดต่อลูกค้า, สเปก (วัสดุ สี infill layer ขนาด) และราคา
4. กลุ่ม LINE ได้การ์ด **🌐 ออเดอร์เว็บไซต์** ส่วนทีมกด **📎 ดาวน์โหลด** ไฟล์ได้ในหน้าคิว

ตั้งค่าโดยใช้คีย์เดียวกันทั้งสองฝั่ง:
```
# apps/print-queue/.env
INTEGRATION_API_KEY=<คีย์ลับ>
# apps/web/.env
PRINT_QUEUE_URL=https://<โดเมนระบบคิว>
PRINT_QUEUE_API_KEY=<คีย์ลับเดียวกัน>
```
สร้างคีย์ได้ด้วย `openssl rand -hex 32` ระบบจะเลือกวัสดุในสต็อกที่ชนิดและสีตรงกับที่ลูกค้าเลือก (ถ้ายังไม่มีในสต็อก จะแจ้งว่า "ไม่มีในสต็อก" ในการ์ด)

### API สำหรับระบบภายนอก (header `X-API-Key`)
| Method | Path | Body |
|---|---|---|
| POST | `/api/external/files` | ไฟล์ดิบ (`application/octet-stream`), header `X-File-Name` (URL-encoded) → `{ id }` |
| POST | `/api/external/orders` | `{ customer, contact, note, items: [{ title, material_type, color, est_grams, est_minutes, qty, price, file_id, note }] }` → `{ order_no }` |

## Deploy ด้วย Docker
```bash
docker build -t print-queue apps/print-queue
docker run -d -p 3000:3000 -v pq-data:/data --env-file apps/print-queue/.env print-queue
```
ฐานข้อมูลและไฟล์ STL เก็บที่ `/data` (ต้องผูก volume ไว้ ไม่อย่างนั้นข้อมูลจะหายเมื่อ redeploy) ถ้า deploy บน Railway ให้ตั้ง Root Directory เป็น `apps/print-queue` แล้วเพิ่ม Volume ที่ `/data`
